# 観測記録skills 計画書

## 1. 目的

`requirements/260424 観測記録作成skills` の内容をもとに、観測記録ページ実装を安定して進めるための **project skill** を設計する。  
今回は **skill 本体の実装は行わず**、必要な責務分割・前提・作成手順・未確定事項を整理する。

想定する skill の役割は、次の依頼を受けたときにエージェントへ実装方針を与えること。

- 観測記録を Markdown から表示したい
- `upload` フォルダの画像込みで observations ページを作りたい
- 年別サイドバー + 日記 + 観測記録ページを整備したい

## 2. 前提整理

### 要件から確定していること

- 観測記録の入力ソースは Markdown
- Markdown と参照画像は `upload` フォルダに置く
- 表示対象は「日記」と「観測記録」
- 左サイドバーに年ごとの日付一覧を表示する
- 観測記録は「タイトル → 天体写真 → 撮影データ → 所感」の順で表示する
- 観測写真はクリックで全画面表示できるようにする

### 追加で確定した方針（2026-04-24）

- **レイアウト・情報順の正本**は `requirements/example.html` とする（PDF は参照しない）
- **複数観測対象**は Markdown 上で **見出し＋ブロックの繰り返し**（各ブロック内は「タイトル → 天体写真 → 撮影データ → 所感」の順を維持）
- **コンテンツ配置**は `upload/<year>/<date>/` の階層で固定する（例: `upload/2024/240410/index.md` と同階層に画像）。年・日付は **パスから決定**し、frontmatter は任意メタ用に留めてよい
- **ルーティング**は動的 `app/observations/[year]/[date]` のみとし、`app/observations/2024/...` のような静的パスは置かない（既存の静的ページは削除済み）

### データ取得の推奨方針（Next.js）

- **第一推奨: ビルド時に `upload/` を読み、SSG で詳細ページを生成する**（`generateStaticParams` で `[year]`・`[date]` を列挙し、ビルド時に `fs` で Markdown を読む）
  - 観測記録は「デプロイ時点でリポジトリ／ビルドコンテキストにファイルがある」前提と相性がよい
  - 本番リクエストでディスク走査に依存しない・CDN 配信で速い
  - 追記・修正の反映は **再デプロイ**が基本。更新頻度が高い場合のみ **ISR**（`revalidate`）やオンデマンド再検証を検討
- **代替**: ローカル検証や超少数ページなら `dynamic = 'force-dynamic'` によるリクエスト時読込も可だが、本番での I/O・キャッシュ設計の手間が増えるためデフォルトにはしない

### 現行実装の状況

- `app/observations/page.tsx` は年別カードの仮データ表示
- `app/observations/[year]/layout.tsx` は現状 `app/observations/<year>` 配下のディレクトリ名を日付一覧として扱う（**実装完了時は `upload/<year>/<date>/` の列挙に置き換える**）
- `app/observations/[year]/[date]/page.tsx` はハードコードされた仮データを描画している
- Markdown 読み込み、画像解決、モーダル全画面表示は未実装
- 静的ルート `app/observations/2024/240410` 等は削除済み（2026-04-24）

### 参照資料の扱い

- `requirements/example.html` は完成イメージ参照として使う（**正本**）
- 保存形式の都合で、そのまま UI テンプレートとして流用する前提にはしない
- 実装時は「構成・余白・情報順」の参照を優先し、HTML の生変換はしない

## 3. skill のスコープ

### 含める内容

1. 観測記録 Markdown の扱い方
2. `upload` 配下のファイル配置前提
3. 年別サイドバー生成の方針
4. 日記セクション描画の方針
5. 観測記録セクション描画の方針
6. 画像全画面表示の実装方針

## 4. 想定する skill 構成

配置先は repo 共有を前提に、**プロジェクト skill は `.codex/skills/observation-record-pages/`** とする（Codex 向けのプロジェクト配下 skills 置き場）。

### 予定ファイル

1. `SKILL.md`  
   skill の発火条件、全体手順、実装時の判断基準を書く
2. `markdown-format.md`  
   観測記録 Markdown の想定フォーマット、必須項目、任意項目を書く
3. `implementation-checklist.md`  
   実装順序と確認観点をチェックリスト化する
4. `templates/observation-entry.md`  
   ユーザーが **複製して** `upload/<year>/<date>/index.md` として書き換え、画像を同階層に置くための **テンプレート本文**。`SKILL.md` からコピー元として参照する。内容は `markdown-format.md` と **常に同期**させる（仕様変更は両方直す）。

初版では script 追加なしで開始し、Markdown 仕様が固まってから必要なら補助スクリプトを検討する。

## 5. skill に書くべき中心ルール

### 5-1. 発火条件

- 「観測記録ページを作る」
- 「Markdown から observations を表示する」
- 「upload フォルダの画像つき日記/観測記録を表示する」
- 「観測記録の sidebar を自動生成する」

### 5-2. 実装原則

- 既存の `observations` ルーティング構造をできるだけ活かす
- 仮データを増やさず、Markdown ローダーへ責務を寄せる
- 日記が存在しないケースを必ず許容する
- フォントや基本色は既存テーマに合わせる
- 表示順・ラベル名・用語を統一する

### 5-3. skill が案内する実装順

1. Markdown データ仕様を確定する
2. `upload` から年・日付・画像を解決するローダーを作る
3. 年別/日付別のインデックスを生成する
4. 日記セクションを描画する
5. 観測記録セクションを描画する
6. 画像全画面表示を追加する
7. 既存仮データを差し替える
8. 表示確認と欠損ケース確認を行う

## 6. 実装フェーズ計画

### Phase 1: コンテンツ仕様固定

- Markdown 1ファイルあたりの構造を決める
- 日記あり/なしの分岐ルールを決める
- 画像参照方法を決める
- 撮影データの表現方法を決める

### Phase 2: データ取得層

- `upload/<year>/<date>/index.md`（固定階層）から Markdown 一覧を取得
- 年・日付は **ディレクトリパスから確定**（frontmatter はタイトル等の任意メタ用）
- サイドバー用の年別インデックスを生成
- 詳細ページ用に 1 件の観測記録を解決

### Phase 3: 表示層

- `app/observations/page.tsx` の年別表示を実データ化
- `app/observations/[year]/layout.tsx` の sidebar を Markdown 起点へ置換
- `app/observations/[year]/[date]/page.tsx` を Markdown 描画へ置換
- 日記ブロックと観測記録ブロックを明確に分離

### Phase 4: 画像 UX

- 本文中画像の表示サイズルールを決める
- 観測写真クリック時の全画面表示を実装
- キーボード/閉じる操作も確認

### Phase 5: 検証

- 日記なしデータで崩れないか
- 画像複数枚で崩れないか
- 年・日付ソートが期待通りか
- モバイル幅で sidebar/本文が破綻しないか

## 7. 現時点の主要論点

### 未確定（skill / 実装前に詰める）

1. Markdown 本文の構造化ルール  
   日記セクションと観測記録セクションの **区切り方**（例: 固定見出し `## 日記` / `## 観測記録` など）を `markdown-format.md` に落とす。

2. Markdown パーサー手段  
   現在 `package.json` に Markdown 系依存はないため、実装段階で `remark` / `next-mdx-remote` 等の要否を判断し、**追加する場合は事前承認**する。

### 確定済み（2026-04-24）

- 参照レイアウトは `requirements/example.html` のみ
- `upload/<year>/<date>/` 階層固定、複数対象は見出し・ブロック繰り返し
- 静的 `app/observations/2024/...` は廃止
- データ取得のデフォルト方針は **ビルド時読込 + SSG**（上記「データ取得の推奨方針」）

## 8. この計画に基づく次アクション

1. Markdown フォーマット案を先に 1 つ決める
2. skill 名を確定する  
   候補: `observation-record-pages`
3. `.codex/skills/observation-record-pages/` に初版ファイルを作る（上記 `templates/observation-entry.md` を含む）
4. テンプレを `upload/` に 1 件コピーして動作検証する（実データが無い場合はダミーで可）

## 9. 完了条件

以下を満たしたら、skill 実装着手可能と判断する。

- skill の責務が「観測記録ページ実装支援」に限定されている
- Markdown 入力仕様の叩き台がある（`markdown-format.md` と `templates/observation-entry.md` の両方）
- 現行 `observations` のどこを差し替えるか明文化されている
- 未確定事項が明示されている
- 追加依存が必要な場合の確認ポイントが整理されている
