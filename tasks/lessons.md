## [2026-07-06] effect本文内の同期setStateはlintエラーになる

### 問題
`Reveal` コンポーネントで `useEffect` 本文内に `setVisible(true)` を直接書いたところ、`react-hooks/set-state-in-effect` エラーで lint が落ちた（reduced-motion 時の即時表示分岐）。

### 原因
React の推奨に反し、effect 本文で同期的に setState するとカスケードレンダーを起こすため、このプロジェクトの ESLint 設定（eslint-config-next）ではエラー扱い。

### 対処
分岐を IntersectionObserver のオプション（`threshold: 0`）に寄せ、setState は必ずオブザーバーコールバック（非同期経路）内で呼ぶ構成に変更した。

### 再発防止
effect 内で状態を即時反映したい場合も、イベント・オブザーバーのコールバック経由にするか、レンダー時に導出できる形（props / 初期化子）へ寄せる。

## [2026-04-14] フォルダリネーム後の Turbopack パニック

### 問題
Next.js プロジェクトのフォルダを `my-app` → `my-ralsite` にリネームした後、
`FATAL: An unexpected Turbopack error occurred` が発生しトップページが表示されなくなった。

### 原因
`.next/` ビルドキャッシュ内に旧フォルダパスが埋め込まれており、
パスの不一致で Turbopack がパニックを起こす。

### 対処
devサーバーを止めてから `.next/` を削除し、再起動するだけで解消。

```powershell
Remove-Item -Recurse -Force ".next"
npm run dev
```

### 再発防止
フォルダ名変更・移動時は **必ず `.next/` を削除してから** 再起動する。

## [2026-04-24] Next.js 16 の Layout で `params` が Promise

### 問題
`next build` 時、`.next/dev/types/validator.ts` で `LayoutProps` の `params` 型不一致（`year` が Promise 内にあるべき）で TypeScript が失敗した。

### 原因
App Router の `layout.tsx` / `page.tsx` では、Next 15 以降 **`params`（および `searchParams`）が非同期**になり、`Promise<...>` として渡される。

### 対処
`params: Promise<{ year: string }>` とし、関数先頭で `const { year } = await params;` する。

### 再発防止
新規セグメントやバージョンアップ後は `npm run build` で型チェックを通し、`page` / `layout` の props 型を公式の `LayoutProps` / `PageProps` に合わせる。

## [2026-04-24] PowerShell で `[]` を含むパス参照が失敗する

### 問題
`app/observations/[year]/...` のようなパスを `Get-Content` で読むと、存在するのに「見つからない」と判定された。

### 原因
PowerShell では `[]` がワイルドカードパターンとして解釈されるため、通常の `-Path` 指定だと意図したファイルに一致しない。

### 対処
`Get-Content -LiteralPath` を使って文字列をそのままパスとして解釈させた。

### 再発防止
Next.js の動的セグメント（`[param]`）を含むファイルを PowerShell で扱うときは、読み書きともに `-LiteralPath` を優先する。

## [2026-04-25] Markdown抽出で `\Z` は JavaScript 正規表現の終端にならない

### 問題
観測詳細で `#### 所感` が常に未表示になった。

### 原因

### 再発防止
Markdownの見出し境界抽出は、複雑な終端正規表現よりも行走査で実装する。特に言語間で挙動差が出るメタ文字（`\Z` など）は避ける。

### 再発防止
ユーザー入力ベースの簡易マークアップは、厳密一致より「正規化して解釈」する実装を初期段階から採用する。

## [2026-04-26] 同一ページ内のセクション切替は hash を使うと静的構成を崩しにくい

### 問題
`About` ページで左サイドバーの選択に応じて右側の本文を切り替えたかったが、Server Component の `searchParams` に寄せるとページ全体が動的化しやすい。

### 原因
Next.js App Router では `page.tsx` で `searchParams` を読むとリクエスト依存になり、固定データだけで完結する UI 切替でもサーバー側の責務が増える。

### 対処
本文データはサーバーで一括ロードし、選択状態だけを client component + `location.hash` + `history.replaceState` で管理した。

### 再発防止
表示データが静的で、切替だけをクライアントで完結できるページは、まず hash やローカル state で構成し、不要に `searchParams` へ逃がさない。

## [2026-07-06] 固定背景Canvasの演出は「不透明なヒーロー画像」の裏に隠れる

### 問題
星のまたたき・流れ星を全ページ共通の固定Canvas（`z-index: 0`）に実装したが、トップページの最初の1画面はヒーロー写真（不透明PNG・100svh）が全面を覆うため、演出がまったく見えなかった。「変わった感じがしない」との指摘につながった。

### 原因
`StarBackground` は `position: fixed; z-index: 0`、`main` は `z-index: 1`。ヒーローの `next/image`（fill・不透明）がその上に描画されるので、ファーストビューでは背景Canvasの描画内容が全部隠れる。流れ星の発生域（画面上部35%）はちょうどヒーロー画像の真裏だった。

### 対処
`StarBackground` に `variant="hero"` を追加し、ヒーローセクション内部の「写真の手前・山シルエットの背後」（`z-index: 2`、山レイヤーよりDOM順で前）に親要素サイズ追従のオーバーレイCanvasとして重ねた。heroバリアントはメテオを高頻度・高輝度に調整。

### 再発防止
背景レイヤーに演出を足すときは、まず「その上に不透明な全面要素がないか」をz-index/DOM順で確認する。ファーストビューに効かせたい演出は、対象セクション内部のオーバーレイとして実装する。
