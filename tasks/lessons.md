## [2026-04-14] フォルダリネーム後の Turbopack パニック

### 問題
Next.js プロジェクトのフォルダを `my-app` → `my-ralsite` にリネームした後、
`FATAL: An unexpected Turbopack error occurred` が発生しトップページが表示されなくなった。

### 原因
`.next/` ビルドキャッシュ内に旧フォルダパスが埋め込まれており、
パスの不一致で Turbopack がパニックを起こす。

### 対処
devサーバーを止めてから `.next/` を削除し、再起動するだけで解消。

```powershell
Remove-Item -Recurse -Force ".next"
npm run dev
```

### 再発防止
フォルダ名変更・移動時は **必ず `.next/` を削除してから** 再起動する。

### 再発防止

## [2026-04-24] Next.js 16 の Layout で `params` が Promise

### 問題
`next build` 時、`.next/dev/types/validator.ts` で `LayoutProps` の `params` 型不一致（`year` が Promise 内にあるべき）で TypeScript が失敗した。

### 原因
App Router の `layout.tsx` / `page.tsx` では、Next 15 以降 **`params`（および `searchParams`）が非同期**になり、`Promise<...>` として渡される。

### 対処
`params: Promise<{ year: string }>` とし、関数先頭で `const { year } = await params;` する。

### 再発防止
新規セグメントやバージョンアップ後は `npm run build` で型チェックを通し、`page` / `layout` の props 型を公式の `LayoutProps` / `PageProps` に合わせる。

## [2026-04-24] PowerShell で `[]` を含むパス参照が失敗する

### 問題
`app/observations/[year]/...` のようなパスを `Get-Content` で読むと、存在するのに「見つからない」と判定された。

### 原因
PowerShell では `[]` がワイルドカードパターンとして解釈されるため、通常の `-Path` 指定だと意図したファイルに一致しない。

### 対処
`Get-Content -LiteralPath` を使って文字列をそのままパスとして解釈させた。

### 再発防止
Next.js の動的セグメント（`[param]`）を含むファイルを PowerShell で扱うときは、読み書きともに `-LiteralPath` を優先する。

## [2026-04-25] upload 配下の画像はそのままでは公開されない

### 問題
`upload/<year>/<date>/index.md` の画像パスを観測詳細ページに表示しても、`public/` 直下ではないためブラウザから直接取得できなかった。

### 原因
Next.js の静的配信は基本的に `public/` が対象で、プロジェクト直下の `upload/` は自動公開されない。

### 対処
`app/upload/[...segments]/route.ts` を追加し、`upload/` を安全に読み出す GET ハンドラで画像配信を実装した。

### 再発防止
ファイルシステム由来の画像を表示するときは、早い段階で「公開経路（`public` か route handler か）」を決めてから画面実装する。

## [2026-04-25] Markdown抽出で `\Z` は JavaScript 正規表現の終端にならない

### 問題
観測詳細で `#### 所感` が常に未表示になった。

### 原因
セクション抽出の正規表現に `\Z` を使っていたが、JavaScript では終端メタ文字として機能しないため、期待どおりに本文が取れていなかった。

### 対処
見出し抽出を正規表現依存から行単位の走査に変更し、`##` / `###` / `####` の次見出しまでを安定して切り出す実装に置き換えた。

### 再発防止
Markdownの見出し境界抽出は、複雑な終端正規表現よりも行走査で実装する。特に言語間で挙動差が出るメタ文字（`\Z` など）は避ける。

## [2026-04-25] 独自装飾タグの正規表現実装はネストを扱えない

### 問題
`{red}...{small}...{/small}...{/red}` のような入れ子装飾を使うと、想定どおりに描画できなかった。

### 原因
単純な正規表現置換は同一文字列中のネスト構造を正しく解釈できない。

### 対処
装飾タグ描画を再帰パーサーへ置き換え、開始タグと終了タグを対応付けながら `ReactNode` を組み立てるようにした。

### 再発防止
入れ子要件がある記法は、最初からトークン走査か再帰下降で実装する。正規表現単体で構文木を作ろうとしない。

## [2026-04-25] 観測本文は独自タグだけでなく最小Markdownも描画する

### 問題
`index.md` の日記本文にある `**太字**` と段落内改行が、そのまま記号文字として表示されて読みづらくなった。

### 原因
本文描画が独自装飾タグ（`{red}` など）専用で、通常Markdownの基本表現を解釈していなかった。

### 対処
独自タグパーサーは維持したまま、プレーン文字列ノードを描画するときに
- `**...**` を `<strong>`
- `\n` を `<br />`
へ変換する処理を追加した。

### 再発防止
観測記録本文は「独自タグ + 最小Markdown（太字/改行）」を標準仕様として扱い、テンプレ変更時は描画側と同時に回帰確認する。

## [2026-04-25] 独自タグは記法ゆれを許容した方が運用で壊れにくい

### 問題
独自タグが「使っているのに反映されない」と見えるケースが出た。

### 原因
タグ解析が厳密一致（`{red}` など固定文字列）前提で、記法ゆれに弱かった。

### 対処
タグトークン解析を導入し、次を許容した。
- 大文字小文字ゆれ（例: `{Red}`）
- 余分な空白（例: `{ red }`）
- エイリアス（`{big}`/`{tiny}`/`{gray}`）

### 再発防止
ユーザー入力ベースの簡易マークアップは、厳密一致より「正規化して解釈」する実装を初期段階から採用する。
